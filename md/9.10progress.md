### 1.3 但 bin_idx 不能直接用,它是**走廊全局**编号
在本地 raw 分片上解析 08-21 07 时 part-00000(14.4M 行 seg_mark=1),6 个跨 4 天的分片复核:

| 事实 | 数值 |
|---|---|
| 一条 observation 内 piece 的 bin_idx 范围 span==nunique | 100.000%(连续无洞) |
| 一条 observation 内 distinct bin_idx | ≤50(max 50) |
| `(bin_idx - 10) // 50 == seg_idx` | 100.000%(6 分片 57M 行全过) |
| `loc = bin_idx - 50*seg_idx - 10` 落在 [0,49] | 100.000%(min 0 max 49) |
| 每个 (map_version, target_link_id) 的 min(bin_idx) | 99.999071% 恰为 10(215,256 个 link,2 个例外) |

即 `bin_idx` 是走廊全局 bin 号(目标 link 从第 10 个 bin 起),`seg_idx` 是目标 link 上的
500m 段号,段内位置 = `bin_idx - 50*seg_idx - 10` ∈ [0,49]。

**格点是绝对的、跨轨迹共享**:seg_idx=3 的 1960 条样本里 1959 条从 bin_idx=160 起,1 条从
163 起(中途汇入)。所以**绝不能按每条轨迹自己的 min(bin_idx) 归一化**,会把那一条整体错位
3 个 bin。→ spatial position 必须用绝对格点 `(bin_idx - 10) % 50`。

## §2 训练侧 reader(已写,未验收)

新文件 `target_link_v1/data/cell_corpus.py`(照 `data/window_stream.py` 的 `_pack`/`collate_*`
契约风格):

- `CellCorpusDataset(IterableDataset)`:一个 item = 一个 training group(≤16 条轨迹)。
  按 (day,bucket) 分区读,groups 和 observations 都是 cell_id 排序写出的,所以一个 cell 的
  observation 是连续切片,searchsorted 定位。worker 分片沿用"同一 permutation 后取 disjoint
  下标"的既有写法。yield 的字段:`x [m,50,3]`、`bin_valid [m,50]`、`traj_valid [m]`、
  `delta_t [m]` + cell_id/K/window/group_id/sample_ids。
- `collate_cells(items)` → 补齐到 `[B,16,50,3]`:x、bin_valid、traj_valid、delta_t、
  **mae_mask(50% whole-trajectory)** + cell_id/K/group_id/sample_ids。
  padding 只在 collate 阶段做,collate 出来的 pad 槽 x=0、traj_valid=0、mae_mask=0。

**pieces → bins 的折叠规则(需要用户确认,已在代码里按默认实现)**:
- `T_diff` = 该 bin 各 piece 求和(跨 link 拆开的一个 bin 仍是一个 bin,过街时间相加)
- `ratio` = 各 piece 求和(内部 bin ≈1.0;段边界切到的 bin <1,这是真实特征)
- `observed` = OR(任一 piece 有 GPS fix 则 1.0)
- `bin_valid`:**默认 "all"** —— bin 的每个 piece 都 T_diff 非 NaN 才算这个 bin 有效。
  理由:T_diff 是求和,丢掉一个 NaN piece 会得到系统性偏小的值(违反语料"不插补"的口径)。
  代码里 `bin_valid_rule="any"` 可切;实测 NaN piece 占 0.42%,两种口径差 ~0.4% 的 bin。
- 无 piece 的 bin:invalid、特征置 0 —— 与预训练 encoder 既有的"缺口"约定一致。
- 无 piece 的情形 `valid` 单独作为 mask,不再进 feature 轴(所以 F=3:T_diff/ratio/observed)。

`mae_mask` 由 (epoch, group_id) 决定,同 epoch 可复现,需在 epoch 之间调 `set_epoch(e)`;
valid 轨迹 <2 条的 group 不遮(with K_min=4 是边角情形,遮掉唯一可见轨迹会让 encoder 没有
可注意的对象)。

### 5.1 在真实分片上跑 preflight,撞到两个会让首次训练直接挂的问题

拿 20260822/bucket=64(obs 1,195,673 行 / groups 97,991 / cells 244,118)实测:

1. **`dt` 有 6 行恰好 = 600.0**,违反 `dt ∈ [0,600)` 的文档契约。成因:`dt = t_seg_enter - window`
   在 double 下算完再落 float32,600 附近的 float32 间距是 6.1e-5,于是 599.99999 被舍入到
   600.0。而 `_pack` 原来写的是 `if delta_t.max() >= 600.0: raise` → **第一次跑就会在第一个
   group 上抛异常**。已改成 `> 600.0` 才抛(超出 float32 间距才是真损坏),并把落在窗口边界的值
   `np.clip` 回 `[0, nextafter(600,0)]`;preflight 同步放宽并把 `dt_edge=6` 打进日志,不静默。
2. **`sample_id` 在分片内不唯一,但在单个 cell 内唯一**。一条 pass 可以在同一个 10min window 里
   进入同一条 link 的两个不同 seg_idx,所以同一 sample_id 会出现在两个 cell 里。reader 的
   `row_of` 是按 cell 内 sample_id 建 dict 的,所以只有 cell 内重复才是问题 —— preflight 改成查
   `(cell_id, sample_id)` 组合唯一,并逐 cell 校验 `K == 该 cell 在本分片的 observation 数`、
   `sum(group_size) == 该 cell 的 observation 数`(不重不漏)、group 的 sample_ids 全在本 cell 内。

## §8 数据长什么样(真实样本剖析,20260821/bucket=64)

### 8.1 缺值约定:IEEE NaN,不是 Arrow null(会绊住 QC 脚本)
本 bucket 145.8 万行 / 1758.8 万 piece,**`pc.is_null(list_flatten(T_diff))` 数到 0**,
而 `np.isnan` 数到 **63,457**——与 `valid=0` 的 piece 数**逐位相等**。即缺值是以 IEEE NaN
写在**非空槽位**里的。任何 QC/验收脚本必须用 `isnan`,用 `is_null` 会得到"语料无缺值"的假结论。
(§4.2 当时用 NaN mask 比对是对的,这次我先用错了 API。)
5 个本地分区核对:`valid=0` 占 0.3608% / 0.3530% / 0.3591% / 0.3473% / 0.3446%,
`observed=1` 占 38.3% / 38.3% / 38.2% / 38.2% / 37.7%。所以缺值确实存在,量级 0.35%。

### 8.2 `valid` 与 `observed` 真的不同(和 §7.2 那条待定问题相关)
分区 1 的 2×2:`valid=1&observed=1` 6,707,156 / `valid=1&obs=0` 10,817,193 /
`valid=0&obs=1` 32,295 / `valid=0&obs=0` 31,162。**valid=0 的 piece 里有 51% 是有 GPS fix 的**
——"有观测"不等于"时间可算"。实测:一条轨迹前 3 格 `observed=0` 但 `valid=1`,
后 4 个 piece `observed=1` 却 `valid=0`(T_diff=NaN)。两个轴不能互推。

reader 侧无问题:`_scatter` 用的是语料 `valid` 列(`vcnt == cnt`,all 规则),且 `np.where(v,t,0.0)`
把 NaN 挡在求和之外,所以 NaN 不会污染 bincount。与 `valid=0 ⟺ isnan` 等价。

### 8.3 两个真实样本(留档,便于日后对照)

## §10 修复 §9-2:presence 与 validity 拆开(cell_mae.py)

`src_key_padding_mask=~bin_valid` 把"洞"和"有 piece 但时间不可信"合并,后者被踢出注意力,
reader 保留的 `ratio`/`observed` 成死代码。但直接放开会把置 0 的 T_diff 当"0 秒"喂进去,

- `bin_proj` 输入 3 → **4**:`bin_valid` 作为第四通道回来,显式标记"这格时间不可信"。
- 注意力 mask 改为 **presence**(`x[:,:,I_RATIO] > 0`,成立因为每 piece 的 `ratio_pct>=1`
  且 reader 把缺席 bin 写成全 0)。只有真洞隐形。
- pooling 仍只在 `bin_valid` 上平均(§9_4 "valid-bin Mean Pooling")。

参数 923,009 → **923,137**(+128,正好一列)。CPU 单测:/tmp/chk.py 构造含洞、含无效格、

静默变义 —— 代码里已注明要改成独立字段。
