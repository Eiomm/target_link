## 1. Loss 问题：从"卡死"到"收敛"的完整修复链

### 1.1 现象与诊断

- `debug_overfit.log`：`ours` + out_dim=128 时 loss 卡在 **0.677 = mean-prediction floor**（log_y 方差，即"只会猜均值"的 MSE）500 步不逃逸；去掉投影层（out_dim=None）能正常降到 0.17。
- `debug_ztarget.log`：对 target 做 z-score 后同配置能逃逸 → **不是 wiring bug，是均值平台期**。
- 根因：`log_y` 未标准化（均值 2.62），早期梯度全被 bias 吸收，representation 分支信号太弱推不动 encoder。

### 1.2 修复链（按杠杆大小依次施加）

| # | 修复 | 位置 | 效果 |
|---|---|---|---|
| 1 | **z-score target**（train-split 统计 `z_y/y_mu/y_sd`，eval `exp(ẑσ+μ)` 还原） | `eta_data.py` / `train_eta.py` | 平台期逃逸：loss 0.93→0.18 |
| 2 | encoder 出口 LayerNorm（`feature_norm`） | `encoder.py` | r 尺度稳定 |
| 3 | overfit batch 循环外缓存 | `train_eta.py` | CPU 发射瓶颈消除，~4x 提速 |
| 4 | 余弦 lr 衰减（5e-3→0） | `train_eta.py` | 消除恒定 lr 谷底震荡（±10%），loss 稳定收敛到 0.107 |

### 1.3 overfit 门槛自校准（1.5×oracle）

- **物理 oracle**（ŷ≡td，逐段 10/vᵢ 求和）在 seed-0 的 K=1 子集上 MAE = **1.173s**（中位 0.21s；17 个 y>60s 长尾样本贡献大头）。
- 旧断言 `K=1 < 1.0s` 定在物理地板**之下**，不可达 → 改为运行时自校准：`assert K=1_MAE < 1.5 × oracle`（`train_eta.py`）。
- 校准依据（同配方实测）：encoder 分支启用 ≈ 1.1~1.3×oracle；分支死亡 ≈ 1.65~1.7×；均值平台期 ≈ 2.5×+。1.5 卡在两群中间。
- oracle 随子集浮动（seed0 1.173s / seed1 1.536s / seed2 0.869s）——验证了自校准设计的必要性。

### 1.4 ⚠️ 双稳态发现（对 Stage 1 是结论级风险）

- 同 seed 同配置（6000ep 全批量余弦）两次运行：loss **0.107**（K=1 1.508s，分支启用）vs **0.249**（K=1 2.001s，**分支死亡**）。
- 死亡态指纹：三项指标与 speed variant（无 encoder）几乎重合（0.236/6.25/1.94）→ 模型退化成只靠 (L, v̄) 标量路径。
- 成因：CUDA 非确定性（`scatter_mean` 的 `index_add_` 反向）微扰 + 全批量训练盆地敏感。
- 4 次运行统计：**3/4 启用，翻转率 25%**。
- **Stage 1 必须带分支启用监控**（如 eval 时置零 r 对比预测变化；或直接看 K=1/oracle 比值），否则 "ours 输给 baseline" 可能只是分支死亡假象。

### 1.5 三变体 overfit 终态（同配方 6000ep 余弦，K=1 子集）

| variant | K=1 MAE | ÷oracle |
|---|---|---|
| **ours**（分支活） | **1.508s** | 1.29× |
| speed | 1.937s | 1.65× |
| speed-mlp | 2.180s | 1.85× |
| oracle | 1.173s | 1.00× |

ours 领先 speed-mlp 0.67s → **A2>A1 的训练集预演成立**（正式判决在 Stage 1 测试集）。

## 2. K 稀疏真相：抽样伪影，不是数据稀疏

- **part 文件按轨迹分片**：part-00002 仅含全小时 241,490 条轨迹中的 **2,781 条（1.2%）**，展开成 22.2万 (轨迹×link) 样本 → 单文件下 (link,window) 的 K 被压低 ~50-85 倍。
- 4 文件验证（08时 part 02/04/11/14）：K=1 从 **60.0%→48.9%**，K 中位 1→2，K p90 4→7。外推全 15 文件 K=1 到个位数。
- **200m 切分不影响 K**：样本 100% 覆盖其 link 全部 sub（9,041 多 sub 组仅 6 个例外），sub 级 K ≡ link 级 K，与 L_sub 无关。
- K 的提升杠杆只有"补齐同一小时的文件"；加天数只加组数不加 K。
- `build_profiles.py` 修复：多文件合并后 1 个重复 sample_id（分片边界泄漏）导致 `InvalidIndexError` → `drop_duplicates` 处理。

### 4.3 已识别的 6 个冲突/待决点

1. **5m bin 消融不可行**：上游数据本身就是 10m bin，5m 无法导出；可行集 {mean, 10m, 20m(合并相邻), 30m+}。
2. **切分口径**：文档写 link split，我们已定时间切分（主线），link 切分留作附加对照 → 待统一进文档。
3. **第二层 scatter_mean 未交代**：样本跨多 sub 时"多个 h_CLS → 样本表示"仍需聚合（大概率 mean）。
4. **K=1 组**：整轨迹掩码遇 K=1 组无 visible 可言，需规则（跳过/强制保留）——完整小时数据正是解药。
5. **B1/B2 消融在 v2 中消失**：V1 spec §12 的 residual 对照是"控制 mean speed 后形状是否有信息"的核心科学验证，建议 v2 保留 residual 变体（encoder `input_mode="residual"` 已实现，接 config 即可）。
6. **"删除 scatter_mean" vs Ablation B**：实现上必须 `aggregation: mean | cls` 可配置，不能真删。

### 4.4 概念澄清（当日答疑沉淀）

- **130 维**= 2(L_n,v̄) + 128(r) 拼接，第一层 Linear 吸收任意维度；维度公平性由 speed-mlp（129 维同参数量）封死。
- **B1/B2 语义**：B2 把 profile 减去自身均值后喂 encoder（物理上无法报告整体快慢，只能说形状），下游仍显式拿 v̄ → B2>B0 即"形状携带独立信息"。
- **下游 ours 输入** = 喂给共享 ETAHead 的特征向量，三 variant 唯一区别。
- **mask 两种语义**：我们现有的三种（pad 屏蔽 / invalid 标记参与 attention 不进池化 / valid-only 池化）是**数据有效性 mask**（被动，输入层）；forecast-mae 的 mask（随机藏 50%、mask token 替换、重建）是**训练目标式 mask**（主动），= spec §10 / v2 §8 要做的。
- forecast-mae（ICCV23）参考结论：两段式（MAE 预训练→下游微调）配方可直接参考其 `mask_token` + 随机掩码实现。
