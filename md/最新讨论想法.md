# Target Link Trajectory Representation v1

## 1. 数据单位

- 每小时划分为 6 个 `10 min window`
- 每条 target link 按原始数据中的 `seg_idx` 划分为约 `500m segment（原始数据划分规则）`
- 一个训练 sample 定义为：
- 每个 sample 内采样 (M) 条 trajectory observation
- 同一 `traj_id` 多次进入同一 link：**按多次独立 observation 处理，不做特殊去重**

---

## 2. 最终需要保留的字段

### 索引 / 分组

- `sample_id`：一次经过的唯一标识，仅用于索引和 debug
- `target_link_id`：所属 target link
- `seg_idx`：500m segment 编号
- `t_ref` + `T_cum`：用于计算 trajectory 进入当前 500m segment 的时间 `t_seg_enter`，再用于划分 10min window 和构造时序位置

### Trajectory spatial profile

- `T_diff`：每个 10m bin / link 子片段的通过时间，作为主要运动特征
- `ratio`：该 link 子片段占 10m bin 的距离比例
- `bin_link_ids`：判断 bin 内子片段属于哪条 link
- `bin_link_obs`：是否存在原始 GPS observation，作为 valid / observation mask

### 不作为当前模型输入

- `traj_id`
- `pass_idx`
- `T_cum`
- speed
- `y_travel_s`（仅 ETA 下游使用）
- 其他道路属性第一版暂不使用

### 3.2 Trajectory 之间的时间位置

对于每条 trajectory，先根据 `seg_idx` 找到当前 500m segment 的起点，并利用 `T_cum + t_ref` 得到进入该 segment 的时间：

`t_seg_enter = t_ref + T_cum(segment start)`

使用 `t_seg_enter` 决定该 trajectory 属于哪个 10min window。

随后计算其在当前 window 内的相对时间位置：

`Δt_k = t_seg_enter,k - T_window_start`，其中 `0 ≤ Δt_k < 600s`。

例如，对于一条长度 1455m 的 link：

```
link
├── seg 0: 0–500m
├── seg 1: 500–1000m
└── seg 2: 1000–1455m
```

同一条 trajectory 可能在不同时间进入不同 segment：

```
09:09:50 进入 link / seg0
09:10:25 进入 seg1
09:11:03 进入 seg2
```

因此不能只使用 link-level 的 `t_enter` 给所有 segment 分配时间窗口，而应分别计算每个 segment 的 `t_seg_enter`。例如 seg0 属于 `09:00–09:10`，而 seg1、seg2 属于 `09:10–09:20`。

在各自 window 内，再计算：

```
Δt_k = t_seg_enter - window_start
```

作为该 trajectory 的 Time Embedding。

将 `Δt_k` 编码成 `Time Embedding`，用于建模同一 10min window 内不同 trajectory 的时序关系。

## 4. 模型流程

```
一个 (link, 500m segment, 10min window)
                │
                ├── trajectory 1
                ├── trajectory 2
                ├── ...
                └── trajectory M

每条 trajectory:
[T_diff, ratio, valid]
        ↓
Trajectory Encoder
        ↓
r_k
        +
TimeEmbedding(t_seg_enter - window_start)
        ↓
trajectory token z_k

M 个 trajectory tokens
        ↓
Random Mask Whole Trajectories
        ↓
[CLS] + visible trajectory tokens
        ↓
Trajectory-level Transformer
        ↓
h_CLS
        ├── MAE Decoder → reconstruct masked trajectories
        └── downstream task
```
