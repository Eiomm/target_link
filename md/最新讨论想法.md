# 当前主线设计与数据契约（V1 Cell MAE）

> 状态：现役主线，2026-09-10 按代码、语料验收结果和《本地开发工作流》统一。
> 若本文与早期 200m sub-link、causal windows 或 curves 文档冲突，以本文、
> `tools/build_corpus.py`、`target_link_v1/data/cell_corpus.py` 和
> `target_link_v1/models/cell_mae.py` 为准。

## 1. 目标与训练单位

目标是学习某段道路在一个 10 分钟窗口内的动态交通表征，用于 ETA、路况预测等下游任务。

当前训练单位是 cell：

```text
cell = (map_version, target_link_id, seg_idx, 10min window)
```

- `seg_idx` 沿用上游约 500m 的固定分段规则，不再执行旧方案中的 200m 二次切分。
- 每个 segment 使用 50 个绝对 10m 空间位置，`bin_pos ∈ [0, 49]`。
- 一个 cell 含 K 条 trajectory observation；训练时最多 16 条组成一个 group。
- 同一 `traj_id` 多次经过同一 link 时，每次 passage 作为独立 observation。

## 2. 当前语料

全量语料位于：

```text
hdfs://DClusterNmg3/user/bigdata-dp/user/junao/target_link/corpus_v1
```

现役目录：

| 目录 | 粒度 | 用途 |
|---|---|---|
| `observations_v2/` | 一行一个 `(cell, trajectory)`，piece 级 ragged 数组 | 训练输入 |
| `training_groups_k3/` | K≥3、最多 16 条轨迹的 group | 新主线训练采样，需先在服务器构建 |
| `training_groups/` | K≥4 的旧 group | 保留作回退与对照 |
| `cells/` | 一行一个 cell | K 分布与验收基线 |
| `observations/` | 不含 `bin_pos` 的旧产物 | 保留兼容，不用于当前训练 |

`observations_v2` 由 `tools/build_corpus.py` 定义。关键字段为：

| 字段 | 含义 |
|---|---|
| `cell_id` | cell 的稳定哈希 |
| `sample_id` | 一次 passage 的唯一标识 |
| `dt` | `t_seg_enter - window_start`，范围 `[0, 600)` |
| `T_diff[]` | 各 piece 的通行时间，IEEE NaN 表示未知 |
| `ratio_pct[]` | piece 占 10m bin 的比例乘 10，范围 1..10 |
| `observed[]` | piece 是否有真实 GPS fix |
| `valid[]` | `T_diff` 是否已知 |
| `bin_pos[]` | segment 内绝对空间位置，范围 0..49 |

`bin_pos` 必须使用上游绝对网格：

```text
bin_pos = bin_idx - 50 * seg_idx - 10
```

不得按单条轨迹剩余的 piece 重新从零编号，否则中途汇入的轨迹会发生空间错位。

## 3. Piece 折叠到 Bin

同一个 10m bin 可能因道路边界包含多个 piece。reader 按 `bin_pos` 折叠：

| 输出 | 折叠规则 |
|---|---|
| `T_diff` | valid piece 求和；只要任一 piece 无效，整个 bin 的时间不可信 |
| `ratio` | 所有 piece 求和 |
| `observed` | 所有 piece 取或 |
| `bin_valid` | bin 存在且全部 piece valid |
| 空 bin | 特征全零，`bin_valid=False` |

三个概念不能混用：

- `ratio` 表示空间覆盖比例。
- `observed` 表示是否存在真实 GPS fix。
- `bin_valid` 表示折叠后的 `T_diff` 是否可信。

缺失的 `T_diff` 是 IEEE NaN，不是 Arrow null；QC 必须使用 `is_nan` 或 `np.isnan`。

## 4. Group 与 Batch

- `K_min=3`，`m_max=16`。K=3 时 mask 1 条并保留 2 条，仍可产生训练梯度。
- K 大于 16 时，按稳定哈希确定性打散，再均分为 `ceil(K/16)` 个 group。
- 每条轨迹只进入一个 group，padding 不写入语料，只在 collate 时产生。
- 每个 epoch 对 group 内约 50% 的整条轨迹做 MAE mask；mask 由
  `(epoch, group_id)` 确定，同一 epoch 可复现。
- padding 槽位不会被 mask。

`collate_cells` 的张量契约：

| key | shape | 含义 |
|---|---|---|
| `x` | `[B, 16, 50, 3]` | `(T_diff, ratio, observed)` |
| `bin_valid` | `[B, 16, 50]` | T_diff 可信 mask |
| `traj_valid` | `[B, 16]` | 非 padding 轨迹 |
| `delta_t` | `[B, 16]` | segment 进入窗口后的秒数 |
| `mae_mask` | `[B, 16]` | 被整条隐藏的轨迹 |

真正参与 loss 的 bin 位置统一由
`reconstruction_mask(batch) = mae_mask[..., None] & bin_valid` 推导，形状为
`[B,16,50]`。不额外保存第二份 mask，避免它与上述两个源 mask 不一致。

当前代码口径中，`bin_valid` 是独立的 attention/pooling mask，不拼入 `x` 的特征轴。
这意味着时间未知的 bin 不参与 level-1 attention；是否改为“保留其 ratio/observed 并增加
valid 输入通道”仍是候选实验，不属于当前冻结实现。

## 5. 模型结构

单条轨迹的 Level 1：

```text
[T_diff, ratio, observed]
  -> Input MLP
  -> absolute bin position embedding
  -> bin-level Transformer Encoder
  -> valid-bin mean pooling
  -> r_k in R^128
```

轨迹间的 Level 2：

```text
r_k + TimeEmbedding(delta_t / 600)
  -> keep visible trajectories only
  -> [CLS] + visible trajectory tokens
  -> Trajectory-level Transformer
  -> h_CLS
```

`h_CLS` 是 cell 的动态道路表征。MAE mask 的单位是整条 trajectory，隐藏轨迹不会作为
Level 2 的 key/value 输入，从而避免目标泄漏。

decoder 当前使用：

```text
(h_CLS, visible group_bin_state, bin position, trajectory delta_t)
  -> reconstructed T_diff per bin
```

重建目标默认在 `log1p(T_diff)` 空间计算逐轨迹 Huber loss，再对 group 等权平均。
验证结果除总体 loss 外，还按原始 cell 的 `K` 报告 `K=3`、`K=4..16`、`K≥17`；
这里使用语料中的 `K`，不能用拆分后最多为 16 的 `group_size`。

主训练规格为 `d_model=256`、8 heads、Level 1/Level 2 各 4 层，约 694 万参数。
相比旧的 128 维 2+2 层模型（约 92 万参数）扩大约 7.5 倍，但对 A100 仍属于中小模型。

## 6. 当前已知结构瓶颈

旧 decoder 只能从一个广播到所有 bin 的 `h_CLS`、bin 位置和轨迹时间生成结果。
Level 1 在进入 Level 2 前把 50 个 bin mean-pool 成单个 `r_k`，因此邻居轨迹具体哪个
bin 变慢的信息被压缩。离线留一群体逐 bin 剖面基线与旧模型表现接近，单纯增加 epoch
或调整学习率无法解决这个瓶颈。

当前实现新增 `group_bin_state [B,50,d]`：对可见、非 padding 轨迹在相同绝对 bin
位置的 Level 1 state 求均值，再输入 decoder。masked trajectory 不参与聚合，避免目标
泄漏。验证探针现在分别报告 `cls_gap`（只清零 `h_CLS`）、`group_bin_gap`（只清零
`group_bin_state`）和 `aggregate_gap`（两路都清零）；旧的 `ablate_aggregate=True`
保留作两路全关的兼容入口。

服务器 smoke 通过后，可继续比较以下结构：

1. 在 Level 1 与 Level 2 之间加入逐 bin 的跨轨迹注意力；
2. 将每条轨迹的 bin token 或下采样后的空间 token 输入 Level 2；
3. 为 decoder 构造逐 bin 群体剖面，同时保留 CLS 作为最终表征。

`level2.forward_tokens()` 已返回逐轨迹的 `h_rows`，当前模型只把它作为
`trajectory_state` 输出，尚未接入 decoder。它可用于实验，但本身仍不包含逐 bin 状态。
