# 数据处理过程（V1）

> 输入：滴滴北京轨迹走廊数据（HDFS `beijing_week1/samples`，本地样本 `part-00002.parquet`）
> 两步处理：① ingest 预处理 → ② spatial profile 构建。更新：2026-09-02

---

## 第 1 步：ingest 预处理

```
输入  data/raw_hdfs/part-00002.parquet    760 万行 bin 级原始数据（160 MB，2 个小时窗）
脚本  tools/ingest.py + configs/ingest.yaml
输出  data/processed/ 下三表 + 统计 json
```

**怎么处理**

1. 过滤 `seg_mark==1`（只留 target link 本体，排除上/下游缓冲）
2. 去重：同 `(sample_id, bin_idx)` 的重复行（segment 重叠产生）保留 `T_diff` 有效且 `ratio` 最大的一行
3. 质量过滤：target 段总耗时 ≤ 0.1s 的样本丢弃
4. 派生：样本速度 `v_sample = L_link_m / ΣT_diff`；时间窗 `window_id = floor(t_enter, 1h)`
5. 聚合 `(target_link_id, window_id)` → `mean_speed`（baseline 特征）

**结果数值**

| 输出 | 规模 |
|---|---|
| `samples.parquet` | 222,063 样本（丢弃 39 个） |
| `bins.parquet` | 2,475,015 行（去重删 76,353 重复 bin，影响 34% 样本） |
| `link_window.parquet` | 108,875 个 (link, window) |
| 覆盖 | 108,768 links；2 个小时窗（2026-08-17 07/08 时） |

- v_sample (m/s)：p10/50/90 = 1.72 / 6.44 / 12.53（去重前 p50=6.35，重复计时被修正）
- L_link (m)：p50=71、p90=224（多数 link 短）
- y_travel (s)：p50=12.3、p90=47.5

## 第 2 步：spatial profile 构建

```
输入  samples.parquet + bins.parquet
脚本  tools/build_profiles.py + configs/profiles.yaml（--l-sub 可切 100/200/300/400）
输出  profiles_l200.npz + link_sub_map_l200.parquet + 统计 json
```

**怎么处理**

1. bin 速度：`v_i = 10 × ratio_i / T_diff_i`（T_diff 是通过该 bin 内 link 所属部分的耗时，半格必须乘 ratio）
2. invalid 判定：`T_diff` NaN/≤0，或 `v > 33.3 m/s`（120km/h 上限）→ speed=0、valid=False
3. sub-link 切分（spec §3）：位置 `s = cumsum(ratio)×10`，`sub_id = floor(s / 200)`，link ≤200m 不切
4. 按 (sample, sub) 分组 scatter 成 padded 数组（max_bins=40，覆盖最大 400m）

**结果数值**

| 输出 | 规模 |
|---|---|
| `profiles_l200.npz` | 263,400 profiles × 40（speeds/valid/observed/lengths + meta） |
| `link_sub_map_l200.parquet` | 122,617 个唯一 sub-link（12.7% 的 link >200m 被切分） |

- profiles/样本 = 1.186；bins/profile：p50=8、p90=20
- v_bin (m/s)：p10/50/90 = 3.45 / 9.63 / 19.61
- invalid bin：19,768 个（0.8%）= T_diff 无效 8,972 + 超速 10,796；其余 99.2% valid
