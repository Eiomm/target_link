## 1. 已实现的规则

- 一条路况样本对应 `(map_version, target_link_id, anchor_ts, sub_id)`，即**建模单元**，不是整条物理 link：`sub_id = floor(spatial_start_m / SUB_LENGTH_M)`，单元长度 `min(SUB_LENGTH_M, L_link_m − sub_id×SUB_LENGTH_M)`。≤200m 的 link 就是一个单元；超长 link 按 200m 切（如 430m → 200+200+30）。跨单元边界的单格按**起点**归属、不裁切，因此单元实际可能多容纳一格，`MAX_BINS` 默认 21。
- V1 主设置：回看 600 秒（10 分钟）、每 600 秒更新，窗口**互不重叠**，同一个 event 只进一个 snapshot。消融用 5/5 与 20/20（`LOOKBACK_SECONDS` 与 `STRIDE_SECONDS` 同时改）。旧的 10 分钟窗 + 1 分钟步长会让同一 event 被约 10 个快照重复引用（展开倍数 `lookback/stride`），造成 `window_members` 规模膨胀与相邻样本高度相关，V1 不采用。
- bin 必须满足 `bin_start_ts >= anchor_ts-W`、`bin_end_ts < anchor_ts`、`available_ts <= anchor_ts`。
- 未走完整条路也可参与；只保留符合上述条件的完整 bin。正在通过的 bin、未来 bin、依赖尚未到达观测的 bin 不进入当前输入。
- `ratio` 始终是空间占比，距离为 `bin_size_m*ratio`。不按时间比例伪造距离，不使用整条通行的未来耗时/均速来筛前缀。
- N 按完整路段的每个 anchor 窗口计数，单位 sample_id。先选通行，再保留其所有合格 bin/子段。`MAX_PASSES=0` 表示不限，不再使用旧的七天每路总 cap。
- 精确空间位置保留，删除中间 bin 不会把前后位置挤在一起。子段按 bin 的空间起点分配；跨子段边界的单格不进行额外匀速裁切。
- 输出目录必须是新目录；不覆盖旧产物。失败的中间目录没有最终 metadata，读取器拒绝把它当完整语料。

这里采用严格 `[t-W,t)` 边界：恰好在 t 结束的 bin 会从下一个 anchor 开始参与。跨窗口起点的 bin 整格排除。它们是第一版明确的边界选择，后续如改成闭区间/交叠裁切，需同时改生成、读取断言和测试。

## 2. 真实数据输入条件：必须先核对

**现有 `beijing_week_biz/samples` 不能未经检查就直接全量提交。** 已知原始字段足以提出时间推导假设，但示例没有证明 `available_ts`，也没有现成的绝对空间位置列。

| 字段 | 类型/含义 | 来源与约束 |
|---|---|---|
| map_version,target_link_id,sample_id | 可转换为字符串 | sample_id 必须是稳定的单次经过键，跨小时/日期不能冲突 |
| bin_idx | 非负整数 | 一条目标路组件对应一个 bin 键；多组件须上游规范化 |
| ratio,bin_size_m | 数值 | 空间占比 `(0,1]`、正 bin 尺寸 |
| T_diff | 秒 | 该目标路组件的已知通行时间，有限且正 |
| L_link_m | 米 | 静态道路长度，不能从窗口中幸存的 bin 推导 |
| seg_mark | 整数 | 只保留 1，即目标路本体 |
| observed | 0/1 | 保留质量信息；0 可以是已可靠生成的插值值，并不意味着未知未来 |
| spatial_start_m | 米 | 当前组件在目标路内的静态起点；用 `--position-column` 映射其他列名 |
| available_ts | epoch 秒 | 当前数值及其所有 GPS/插值/地图匹配依赖最早确实可用的时刻；用 `--availability-column` 映射 |
| bin_start_ts,bin_end_ts | epoch 秒 | 默认显式输入；区间长与 T_diff 在 1ms 容差内一致 |

可选 `--time-source cumulative`（提交脚本 `TIME_SOURCE=cumulative`）：使用 `bin_end_ts=t_ref+T_cum`，`bin_start_ts=bin_end_ts-T_diff`。只有核实生产端组件级累计时间语义之后才使用。**此模式仍然要求真实的可用时间和静态空间位置，不会用结束时间替代 available_ts。**

空间位置需由生产端/静态几何映射提供。不能在窗口过滤后 `cumsum(ratio)`，因为那会闭合空间空洞；也不能仅用全局 bin_idx×10，因为走廊包含上游缓冲且目标路边界可能落在半格中。

同 `(map_version,link,sample,bin_idx)` 的完全相同记录去重，保留首次可用时刻。字段有冲突时拒绝处理，防止离线修订值覆盖历史输入。旧的“优先最大 ratio”并不能自动当作可靠的实时版本规则。如原表存在组件重叠或事后修订，先在上游规范化并保留版本的可用性证据。

缺失/非法可用时间直接报错；其他异常值排除并记录 `audit.rejected_rows`。单格超速阈值默认 33.3m/s，可通过 CLI `--max-speed` 设置。生产方若只在整趟结束后给出数据，即使字段名叫 available_ts，也无法提供当时的未完成片段，需要先改上游。

## 4. Spark 正式运行入口

下面占位路径必须替换为**已规范化且符合第 2 节契约**的输入，而不是直接把原始表复制改名。anchor 起止为 epoch 秒，起点包含、终点不包含，均须对齐 STRIDE_SECONDS。

```bash
export INPUT_GLOB='hdfs://你的集群/规范化事件/day17/*.parquet,hdfs://你的集群/规范化事件/day18/*.parquet'
export OUT_DIR='hdfs://你的集群/你的目录/windows_v1_run01'
export ANCHOR_START=1786896000
export ANCHOR_END=1787500800
export LOOKBACK_SECONDS=600
export STRIDE_SECONDS=600
export MAX_PASSES=0

# 先仅打印命令，不提交。
MODE=dry bash legacy/scripts/submit_windows_yarn.sh

# 输入契约及小样本验收后，服务器上执行。
# export HADOOP_USER_NAME=你的账号
# MODE=yarn bash legacy/scripts/submit_windows_yarn.sh
```

上面的 epoch 范围为北京时间 2026-08-17 00:00 至 2026-08-24 00:00；输入示例只有两天，**七天运行要补齐全部输入路径和首窗之前的预热历史**。按进入时间落盘的长通行可能来自更早分区，不能只按最近 W 分钟的目录读取。

可一次提交一个七天任务；也可按日期输出多个独立目录。当前训练入口一次读取一个 corpus，分日输出需另做一致的归并与 metadata，不能手工复制成貌似一个完整目录。先用少量路和短时段测窗口重叠造成的输出放大，再选择全量资源。

其他环境变量：`CAP_SEED`、`TIME_SOURCE`、`AVAILABILITY_COLUMN`、`POSITION_COLUMN`、`SUB_LENGTH_M`、`MAX_BINS`、`CURVES_PARTITIONS`、`SHUFFLE_PARTITIONS`、`QUEUE`、`MAX_EXECUTORS` 等见脚本。`MODE=local` 使用当前/指定的 `PYTHON`，输入同样通过 INPUT_GLOB 指定，不再被 DAY 覆盖。

可选 `LINKS=hdfs://.../static_road_universe`：表至少含 map_version,target_link_id,**link_length_m**——空窗按建模单元展开，单元网格必须由静态长度推出，缺此列直接报错。生成包括空窗在内的单元×anchor 清单。不传则只记录有合格观测的单元，metadata 标注 `nonempty_only`，不能由此统计全路网覆盖率。完整路网×每分钟网格也有规模成本，应先限定路集合。

## 5. 输出与模型读取格式

```text
windows_v2_run01/
  window_curves/       每行=一个 snapshot 内一次经过在该建模单元上的一段曲线，带 unit_start_m/unit_length_m
  window_members/      每行=一个 snapshot 关联的一个可用 bin，含审计时间
  snapshots/           每行=建模单元+anchor；含采样前后通行数（按父 link 计）、空窗标记、均速基线
  window_meta.json.d/  格式版本、W/S/N/seed、输入范围、时间契约、代码 SHA256、异常计数
```

curves 中保留精确位置和时间的 `bins` struct 数组；读取器保留位置空洞，按 snapshot 边界聚合，支持一个组跨 Parquet batch，并避免多 worker 重复取分片。写出时按 snapshot 哈希分片、分片内排序、禁用按行数切文件。不要自行重分片或重排后沿用旧 metadata。

模型输入为扁平曲线数组＋snapshot/pass 分组索引。每条 bin 的特征是 `f_i = [Δt_i, ratio_i, observed_i]`，再加一条独立的空间位置编码 `p_i = s_i/L_unit`；`Δt` 直接使用、不转成速度（定长 bin 下 Δt 已经表达快慢），`ratio_i = distance_m/bin_size_m` 由固定网格还原。不输入完整通行 y/均速。粗粒度年龄**不再是默认特征**：`available_ts` 属于因果可用性门控，不与运动特征混用；`--time-features curve|bin` 保留为消融（`bin` 仍可能存在相邻时间推导捷径，需单独对比）。`--bin-size-m` 必须与生产端 bin 网格一致，否则 `ratio` 与重建目标会被系统性缩放。

读取器默认每个 snapshot 最多 512 条子段曲线，超过则明确报错，不截断、不拆组。热点路段应先设置窗口内 MAX_PASSES；如需提高读取上限，先评估第二层 attention 随组大小的平方开销。

第一层编码一条 trajectory 在**一个建模单元**内的 bin 序列；第二层聚合同一 `(建模单元, anchor)` 的全部 trajectory，输出该单元的动态表征（`snapshot_id` 因此含 `sub_id`，一条 1455m link 在一个 anchor 上产出 8 个独立样本，而不是 1 个整路样本）。位置编码用单元内相对位置 `(spatial_start_m − unit_start_m) / unit_length_m`，不是除以物理 link 长度。`MAX_PASSES` 的限流仍按**父 link** 计数：一辆车穿过 8 个单元只算一次，不会被重复计数。

训练目标是 `Δt_eff = Δt × bin_size / distance`（等效 10 米时长，partial bin 缩放到同一基准）的 Huber 重建损失，`--target-transform log1p|raw` 控制是否套 log1p（默认 log1p）。**mask 单元是整条 trajectory**（不是 bin）：多轨迹 snapshot 里每条轨迹以 `--whole-pass-probability` 独立隐藏，并夹紧到「至少隐藏一条、至少保留一条可见」；只有单轨迹 snapshot 退化为曲线内连续片段 mask（`--mask-ratio`），因为没有任何其他轨迹可以拿来重建它。`--whole-pass-probability 0` 关闭整条轨迹路径、所有 snapshot 都走片段 mask（span-only 消融）。整次经过的所有子段一并隐藏 Δt 与 observed，**ratio 与位置（几何）保留**，解码器查询同样只给几何。空间空洞不作为补零的监督目标。第二层序列是 `[CLS] + 可见轨迹 token + 每条被整条隐藏的轨迹一个 MASK token`：被隐藏轨迹的第一层表征**被替换而不是附加**，它只能经由聚合回到解码器。解码器输入是「几何 query + 第二层 token 隐状态」（`--decoder-input cls|hidden` 决定读 token 隐状态还是纯 CLS），**不接第一层曲线表征**——V2 的教训是给了 skip 之后解码器绕过 CLS，CLS 分支死亡（loss 卡在均速基线附近）。训练日志里的 `val_aggregate_gap` 是这个分支的存活监控：把第二层状态置零后损失应当明显变差，gap 趋近 0 就说明解码器没在用聚合结果。单 bin 曲线仍参与聚合；无可遮挡值且不能跨轨迹重建的窗口不计重建损失，日志单独计数，防止全零损失被当成训练成功。

## 6. GPU 训练与导出

先把整个 corpus 同步到训练机的本地/NFS 目录，保留三张表和 metadata 的目录结构。当前读取器不直接读取 HDFS URI。

编辑 `legacy/configs/pretrain_windows.yaml` 的 data/out 及三个时间边界，或用 CLI 覆盖：

```bash
python tools/train_windows.py --config legacy/configs/pretrain_windows.yaml \
  --data /nfs/你的目录/windows_v1_run01 \
  --out runtime/pretrain_windows_run01 \
  --train-end 1787241600 --val-start 1787242200 --val-end 1787328000

python tools/encode_windows.py \
  --data /nfs/你的目录/windows_v1_run01 \
  --checkpoint runtime/pretrain_windows_run01/last.pt \
  --out runtime/representations_run01.parquet --device cuda
```

输出训练指标和 `last.pt`；checkpoint 保存模型构造参数、训练配置与数据契约。导出得到 snapshot_id/map_version/target_link_id/anchor_ts/representation，可供后续 ETA/路况任务按路段和时刻连接。导出只包含非空窗口；空窗在 snapshots 表中有记录，业务回退策略尚未定义，不能将缺失向量默认为“畅通”。

边界须满足 `val_start >= train_end + W`，训练 anchor `<train_end`，验证 anchor 位于 `[val_start,val_end)`，避免相邻窗口共享同一个 bin。**这不保证长通行的不同 bin 不会跨两侧，也不保证不同轨迹属于不同车辆**。若要严格 passage/车辆独立评估，需另做 ID 隔离；本版不宣称实现。未来下游标签还需按预测 horizon 额外清理边界。
