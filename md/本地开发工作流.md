### 1.2 一行 = 一个 (cell, 轨迹) 观测，ragged

`observations_v2` 的列（`tools/build_corpus.py` 的 docstring 是权威版本）：

| 列 | 类型 | 含义 / 陷阱 |
|---|---|---|
| `cell_id` | int64 | `xxhash64("map_version\|target_link_id\|seg_idx\|window")` |
| `sample_id` | string | 上游 `traj_id#link#pass#event_hour` |
| `dt` | float | `t_seg_enter - window_start`，**在 [0,600) 内**，600.0 会被 reader 夹到 `nextafter(600,0)` |
| `n_pieces` | int16 | ragged 长度，≤50 bins，实测最大 51（一个 bin 被链路边界切开会多一片） |
| `T_diff[]` | float32 | 逐片通行时间，**NaN 原样保留** |
| `ratio_pct[]` | uint8 | 逐片占其 10m bin 的比例 ×10，∈ 1..10 |
| `observed[]` | bool | 该片有 GPS 定位 |
| `valid[]` | bool | `T_diff` 不是 NaN |
| `bin_pos[]` | uint8 | **空间 token 位置，0..49**（见下） |
| `map_version`/`target_link_id`/`seg_idx`/`window` | | 冗余存下来，后面几级不再读 raw |

**`bin_pos` 是绝对栅格，禁止按轨迹重归一化。** 一条轨迹穿过 500m 段 = 50×10m bin；
raw `bin_idx` 是全走廊编号，`seg_idx` 是 500m 段号，实测恒等式
`(bin_idx - 10) // 50 == seg_idx`（100%，4 天 57M 行），于是
`bin_pos = bin_idx - 50*seg_idx - 10` 恰好落在 [0,49]。
栅格为同一 cell 的所有轨迹共享：seg_idx=3 时 1959/1960 条样本从 `bin_idx=160`
起步，有 1 条从 163 中途汇入 —— 一旦按轨迹重归一化，这一条会整体错 3 个 bin。
`collate_cells` 会 assert 0..49。

### 1.3 valid / observed / present 是三件事（最容易改错的地方）

- `observed` = **GPS 有定位**。
- `valid` = **T_diff 已知**。corpus 从不插补。
- 折叠到 bin 级后：`bin_valid = present & (该 bin 的所有片都 valid)` ——
  必须**全部片**都 valid，因为 `T_diff` 是**求和**，丢掉一个 NaN 片会静默低估。
- `present` = 该 bin 至少有一片。reader 里 `present = ratio > 0`（每片 `ratio_pct ≥ 1`，
  缺席的 bin 被写成全零）。

**piece → bin 的折叠规则**（`cell_corpus._scatter`，改 reader 时不许动）：

| 量 | 规则 |
|---|---|
| `T_diff` | 各片**求和**（NaN 片由 `where(v, t, 0)` 挡在外面） |
| `ratio` | 各片**求和** |
| `observed` | 各片**取或** |
| `bin_valid` | **全片 valid** 才 valid |
| 无片的 bin | 全零 + invalid |

折叠后 `x` 的第 0 列对 invalid bin 是 0，`ratio`/`observed` 仍保留在 reader 输出中。
**当前冻结实现**把 `bin_valid` 作为独立 attention/pooling mask，不拼入三维特征轴；
因此 invalid bin 不参与 Level 1 attention。把 presence 与 validity 分开、将
`bin_valid` 作为第 4 通道，是后续可做的消融实验，不是当前代码契约。

### 1.4 NaN 不是 null（踩过一次）

**缺失值是存在非 null 槽位里的 IEEE NaN，不是 Arrow null。**

```python
pc.is_null(t)   # → 0 行  ← 骗人的
np.isnan(t)     # 或 pc.is_nan(t) → 真实数量
```

实测 63,457 个 IEEE NaN 片 == 全部 17,587,806 片中 `valid=0` 的片数，逐位相等。
任何 QC/统计脚本判缺失**必须用 `is_nan`**。用 `is_null` 会得出"没有缺失值"的错误结论
并紧接着在 `bad[0]` 上 IndexError。

本地分区实测：`valid=0` 占 0.36%/0.35%/0.36%/0.35%/0.34%，`observed=1` 占 38.3%/38.3%/38.2%/38.2%/37.7%。

### 1.5 group 策略（策略在 reader，不在语料）

- 一个 **cell** = `(map_version, target_link_id, seg_idx, 10min window)`。
- 一个 **group** = 一个 cell 的最多 `m_max=16` 条轨迹；新主线 `K_min=3`。
- K>16 时按 `hash("cell|sample_id")` 确定性乱序后**均分**成 `ceil(K/16)` 组
  （实测 K=28 → 2 组），每条轨迹恰好用一次。
- 50% **整条轨迹**掩码，由 `(epoch, group_id)` 决定 —— 同一 epoch 重跑完全一致。
  换 epoch 要调 `set_epoch`。
- padding **只在 collate 发生**，语料里不物化 16 槽。

### 1.6 张量契约

`collate_cells` 返回 `[B, 16, 50, F]`，`F = (T_diff, ratio, observed) = 3`：

| key | 形状 | 说明 |
|---|---|---|
| `x` | `[B,M,50,3]` float32 | 原始特征 |
| `bin_valid` | `[B,M,50]` bool | 该 bin 的 T_diff 可信 |
| `traj_valid` | `[B,M]` bool | 槽位是真实轨迹（padding 为 False） |
| `delta_t` | `[B,M]` float32 | 秒 |
| `mae_mask` | `[B,M]` bool | 整条轨迹被掩码 |
| `m_max` / `n_bins` | int | 16 / 50 |

**padding 槽位约定**：全零 + `traj_valid=0`，且 `mae_mask` **永不**覆盖 padding。
loss 与指标使用唯一的 bin 级选择器
`reconstruction_mask = mae_mask[...,None] & bin_valid`。训练仍优化 raw/log1p
空间的 Huber；日志额外报告 `bin_mae_seconds` 和 `bin_rmse_seconds`。

### 1.7 冻结结构

`md/最新讨论想法.md` 统一后的一级结构：
`Input MLP → Position Embedding → Transformer Encoder → valid-bin Mean Pooling → r_k ∈ R^128`。
`Codex` 复核时指出过两个偏离点（时间嵌入须是 `delta_t/600 → 小 MLP`；轨迹编码器
须有 bin 级 Transformer），现已在 `cell_mae.py` 收敛。

## 二、需要改动的地方

### 2.1 核心：逐 bin 群体通道（已实现，待服务器 smoke）

旧版 `cell_mae.py` 的 decoder：

```python
base = h_cls.unsqueeze(1).expand(B, M, -1)      # 一个 d 维向量，广播到 50 个 bin
raw  = decoder(cat([query, base...]))           # query = f(dec_pos_emb(n), time_emb(delta_t))
```

所以 `prediction[b,m,n]` **只能**是 `(h_cls[b], pos_n, delta_t[b,m])` 的函数。
而每条轨迹的 50 个 bin 在 level-1 就被 valid-bin mean-pool 成了 `r_k` ——
**邻居"第 30 个 bin 堵了"这个信息，在进 level-2 之前就已经被平均掉了**，
decoder 无论多深都拿不到。这是 loss 平掉的原因，加 epoch / 调 lr 不会动。

**离线实测（bucket=64，复算 reader 的折叠规则，逐轨迹 Huber）**：

| 预测器 | Huber |
|---|---|
| 最优常数（log1p 空间） | —（逐 bin 0.0857） |
| 留一群体剖面（直接抄同组其他轨迹的逐 bin 值，**零参数**） | **0.0720** |
| 改造前模型（train / val） | 0.0726 / 0.0686 |

**模型比零参数基线还差 0.8%。** 当前本地改造已在 Level 1 输出后对可见轨迹的
同位置 bin state 做均值，形成 `[B,50,d]` 的 `group_bin_state`，并连同 `h_CLS`、
位置和 `delta_t` 输入 decoder。masked trajectory 和 padding 不参与该通道，避免目标泄漏。
仍可继续比较以下方向：
- level-2 的 token 不再是 `r_k`，而是每条轨迹的 50 个 bin token（或先做一次
  跨 bin 下采样，如 50 → 10），让 level-2 能学到"哪个 bin 在堵"；
- 在 level-1 和 level-2 之间加一条逐 bin 的跨轨迹注意力；
- decoder 的 query 不能只是 `(pos, delta_t)`，要能读到一个逐 bin 的群体剖面。

### 2.2 `h_rows` 仍只作为输出（保留后续实验）

`level2.forward_tokens()` 返回 `(h_CLS, h_rows)`（窗口线 9.9 就是为这个改的），
`cell_mae.forward` 把它存进了 `state` 却**只返回、不喂 decoder**：

```python
state[keep] = h_rows
...
base = h_cls.unsqueeze(1).expand(B, M, -1)      # ← state 没进这里
```

窗口线的 docstring 明说这条跳连是"keeps the CLS readout from being bypassed"，
cell 线还留着旧写法。**注意方向**：h_rows 是 level-2 输出的逐 token 状态，
仍然不是 level-1 的逐 bin 状态 —— 接它不会直接解决 2.1，但它是 level-2
唯一还带 token 结构的出口。

### 2.3 `bin_valid` 输入方式（已按当前代码定档，保留消融方向）

当前 `bin_proj` 使用 `Linear(N_FEATURES)`，`N_FEATURES=3`；attention mask 为
`~bin_valid`。`bin_valid` 是独立 mask，不拼入 `x`。

两种立场的差异如下，当前采用右侧；左侧只作为显式消融方案：

| | 候选实验：presence mask + valid 通道 | 当前主线：validity mask |
|---|---|---|
| 无效 bin（有 piece、时间 NaN） | 保留在注意力集，`bin_valid` 当第 4 通道区分"未知"与"0 秒" | 整个排除出注意力与 pooling |
| 代价 | 参数 +128 | reader 保留下来的 `ratio`/`observed` 在无效 bin 上成死代码 |
| `cell_corpus.py` docstring | 一致 | **冲突**（reader 明说无效 bin 保留 ratio/observed） |

若要做候选实验，模型、reader 契约和测试必须一起切换，不能只改 attention mask。
旧的 presence 语义测试不再作为当前主线的通过标准。

   脚本通过 `--val-last-only` 只在最后一个 epoch 读取周日；结果作为 weekend-domain /
   时间外推测试，不再反向调参。

两者都纳入每天 `bucket=0..127`，并用 `--groups-per-partition 4096` 从**每个** day/hash-bucket
稳定抽样，避免全局 `MAX_BATCHES` 提前停止后只读到少数存储分区。每个 hash bucket 内
混有当天多个 10 分钟 `window`。Stage A 每 epoch 最多约
262 万 group，Stage B 最多约 315 万 group；这里的“完整”指所有时段都参与，并非穷尽
每个 bucket 的全部 group。

**k8s 平台规则（硬约束）：**

- 启动命令**只能是一个 sh 脚本路径**；所有参数必须写死在 sh 内部、有默认值、
  不依赖任何预先 export 的环境变量。
- 想要新参数组合，**改 sh 脚本里的 `export`**，不要在平台上拼命令行。
- 日志直接落 stdout，产物落 NFS `runtime/`（已被 gitignore）。

### 4.3 看结果

```bash
ls -t runtime/cell_train_smoke_a100_*/          # 最新一次
cat runtime/cell_train_smoke_a100_*/metrics.jsonl
```

`metrics.jsonl` 每 epoch 一行；关注 `loss`、`cls_gap`、`group_bin_gap` 和
`aggregate_gap`。

本次逐 bin 群体通道增加了模型参数，旧 `target_link_cell_mae_v1` checkpoint 与新结构不兼容；
新 checkpoint 的 format 为 `target_link_cell_mae_v1_group_bins`，需要重新训练。

验证集前 `probe_batches` 个 batch 会在相同样本上运行四次：正常、仅消融 `h_CLS`、仅消融
逐 bin 群体状态、两者同时消融。日志字段为：

- `ablation_probe_loss`：四组比较共同使用的正常 loss；不要拿全验证集 `loss` 直接相减。
- `cls_ablated_loss` / `cls_gap`：只清零 `h_CLS`，衡量 Level-2 全局表示的边际贡献。
- `group_bin_ablated_loss` / `group_bin_gap`：只清零逐 bin 群体状态，衡量局部画像的边际贡献。
- `aggregate_ablated_loss` / `aggregate_gap`：两路都清零；保留该旧字段以对比历史日志。

每个 `gap = ablated_loss - ablation_probe_loss`。gap 接近 0 表示当前 decoder 基本不依赖该路；
正 gap 越大表示清零后的损失越明显。消融是诊断而非训练目标，也不能单独证明表示高于简单统计基线。

`supervised_groups` 现在按实际有重建目标的 group 计数；`supervised_batches` 单独记录批次数。
