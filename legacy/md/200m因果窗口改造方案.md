# Link-level Multi-Trajectory MAE：数据处理与训练流程设计（历史 200m 因果窗口方案）

> 已由 `md/最新讨论想法.md` 的 500m Cell MAE 主线取代，仅作设计追溯。

1. 目标

目标是学习一个 dynamic road representation（动态道路表征）。

对于某个道路 modeling unit（原始短 link，或长 link 切分后的 segment）和某个时间窗口，收集该窗口内多条车辆 trajectory / pass，通过：

10m bin-level motion profile
        ↓
Trajectory Encoder
        ↓
trajectory representations
        ↓
随机 mask 整条 trajectory
        ↓
Multi-Trajectory MAE
        ↓
CLS Token
        ↓
dynamic road representation

该 representation 后续可用于 ETA、RP / traffic prediction 等 downstream task。

2. 数据层级

需要明确以下层级，不能混在一起：

Raw GPS points
    ↓
Trajectory / Pass
    ↓
Physical Link
    ↓
Modeling Unit
    ↓
10m Spatial Bins
    ↓
Bin Event
    ↓
Time Window / Snapshot
    ↓
Multi-Trajectory Sample

其中：

Trajectory / Pass：一辆车一次经过目标道路的轨迹。

Physical Link：地图中的原始 road link。

Modeling Unit：

若原始 link ≤ 200m，直接保留；

若原始 link > 200m，再切成多个 segment；

因此 200m 是最大长度，不是固定长度。

Bin：沿道路方向按 10m 切出的空间单元。

Snapshot：某条 modeling unit 在某个 anchor time 下的因果历史视图。

3. Raw Samples

原始 samples 是 producer 视角的数据。

每行主要描述：

某条 trajectory 在某个 spatial bin 上对应的运动信息。

典型字段：

sample_id
target_link_id
bin_idx
link_id
ratio
T_diff
observed
seg_mark
...

例如：

sample_id = 10007212890835753880#125121851#000
target_link_id = 125121851
bin_size = 10m
link_length = 1455m

对于固定 10m spatial bin：

[
au =
[\Delta t_1,\Delta t_2,\ldots,\Delta t_N]
]

其中 Δt = T_diff。

3.1 为什么直接使用 Δt

不需要额外转为 speed。

因为对于固定长度 bin：

[
v_i=rac{10}{\Delta t_i}
]

因此 Δt 已经能够直接表达车辆运动快慢：

Δt 小 → 车辆快
Δt 大 → 车辆慢

模型直接学习 Δt 即可。

4. Ratio 的含义

ratio 需要和时间窗口里的“轨迹完成比例”区分。

4.1 Raw Ratio 的主要含义：空间归属比例

更准确地说：

rac{
ext{bin } i 	ext{ 中属于 physical link }j	ext{ 的长度}
}{
ext{bin size}
}
]

情况 1：完整 10m bin 属于一个 link

ratio = 1.0

情况 2：一个 10m bin 跨两个 physical links

真实样本中：

bin[155]

links = [125121851, 7524951]
ratio = [0.5, 0.5]

含义：

5m 属于 link A
5m 属于 link B

另一个例子：

bin[157]

ratio = [0.4, 0.6]

即：

4m 属于 link A
6m 属于 link B

情况 3：trajectory / corridor 尾部不足完整 10m

例如：

bin[165]

ratio = 0.5

说明该 bin 实际只有约 5m。

5. observed 的含义

observed 表示该 bin 是否具有真实 GPS fix。

observed = 1

表示：

该 bin 对应位置存在真实 GPS 上报点。

observed = 0

表示：

该 bin 本身没有直接 GPS fix，其时间 / motion 信息主要由前后 GPS fix 插值得到。

因此：

observed
= observation source / observation quality indicator

它和 ratio 没有相同语义。

6. Events：因果事件层

events 是从 raw samples 到 window corpus 的中间层。

它的目的不是改变 motion 数据，而是补齐：

这个 bin 在哪里？
什么时候发生？
什么时候真正可以被使用？

每个 event 可以抽象为：

[
e_i =
(
sample_id,
bin_idx,
spatial_start_m,
bin_start_ts,
bin_end_ts,
available_ts,
\Delta t_i,
...
)
]

6.1 四个关键字段

spatial_start_m

表示：

该 bin 在当前道路 / modeling unit 中的绝对空间起始位置。

例如：

bin0 → 0m
bin1 → 10m
bin2 → 20m
...

不能只使用过滤之后的 bin index，因为删除中间 observation 后，空间位置不能被重新挤压。

bin_start_ts

表示：

车辆在插值意义上进入该 bin 的时间。

bin_end_ts

表示：

车辆在插值意义上离开该 bin 的时间。

available_ts

表示：

该 bin 的耗时信息在真实在线条件下什么时候才真正可以知道。

这是因果性最关键的字段。

对于插值 bin：

bin_end_ts < available_ts

是完全正常的。

例如：

GPS Fix A -------------------------- GPS Fix B
              bin9
              bin10
              bin11
              bin12

虽然根据 A/B 可以事后插值得到：

bin9 end
bin10 end
bin11 end
bin12 end

但这些时间只有等到下游 GPS Fix B 到达后才真正能够计算出来。

所以：

physical event time ≠ information available time

7. Snapshot / Window

Snapshot 定义为：

[
(	ext{modeling unit},\ anchor_ts)
]

表示：

在 anchor 时刻，站在当前道路上，只使用当时真正已经知道的历史信息。

一个 event 进入 snapshot 至少需要满足：

[
bin_end_ts < anchor
]

[
available_ts \leq anchor
]

以及：

[
bin_start_ts \geq anchor - lookback
]

即：

已经发生
+
当时已经知道
+
仍然位于历史窗口内
=
可以进入 snapshot

8. Window 长度与 Stride

原方案：

lookback = 10 min
stride   = 1 min

会造成约 90% 的相邻窗口重叠。

理论展开倍数：

[
rac{600}{60}=10
]

即同一个 event 可能被约 10 个 snapshot 重复引用。

这也是 window_members 规模膨胀约 10 倍的主要原因。

V1 推荐

首先使用：

window length = 10 min
stride        = 10 min

即：

08:00–08:10
08:10–08:20
08:20–08:30
08:30–08:40
08:40–08:50
08:50–09:00

一个小时对应 6 个基本 snapshot。

推荐 ablation：

5 min window  + 5 min stride
10 min window + 10 min stride   ← V1 主设置
20 min window + 20 min stride

暂时不优先采用：

10 min window + 1 min stride

因为它会带来：

大量数据重复；

大规模 window_members；

相邻训练样本高度相关；

effective sample size 远小于表面样本数量。

9. Partial Trajectory 不应该用 ratio 表示

例如：

09:09 车辆进入 link
09:10 snapshot 到达
但车辆还没有走完整条 link

这属于：

partial trajectory / causal availability

不应该和 raw ratio 混为一谈。

这类情况应该通过：

available_ts
+
valid mask

表达。

例如 80m modeling unit 共 8 个 bin：

bin0  valid=1
bin1  valid=1
bin2  valid=1
bin3  valid=0
bin4  valid=0
...

因此三个概念需要固定：

ratio
= 空间覆盖 / link 几何归属

observed
= 是否存在真实 GPS fix

valid
= 当前 snapshot 时刻是否 causally available

10. Modeling Unit 的长度

不应该假设所有 modeling unit 都是 200m。

正确规则：

if link_length <= 200m:
    modeling unit = original link
else:
    split link into segments <= 200m

例如：

80m link
→ 1 unit
→ 8 bins

145m link
→ 1 unit
→ 15 bins 左右

430m link
→ 200m + 200m + 30m

因此：

[
L_{	ext{unit}}\leq 200m
]

而不是：

[
L_{	ext{unit}}=200m
]

对应 bin 数：

[
N=
\left\lceil
rac{L_{	ext{unit}}}{10}

ight
ceil
]

因此 trajectory 是 variable-length sequence。

Batch 时需要：

Padding
+
Attention Mask

11. Bin-level 输入设计

V1 中建议每个 bin 使用：

[
f_i =
[
\Delta t_i,
ratio_i,
observed_i
]
]

然后：

[
e_i = MLP(f_i)
]

再加入 Spatial Position Embedding：

[
x_i =
MLP(
[
\Delta t_i,
ratio_i,
observed_i
]
)
+
E_{pos}(p_i)
]

其中：

[
p_i = rac{s_i}{L_{	ext{unit}}}
]

(s_i)：当前 bin 在 modeling unit 中的空间起始位置；

(L_{	ext{unit}})：当前 modeling unit 的真实长度。

12. 为什么 Position Embedding 用空间位置

Position Embedding 应回答：

当前 bin 位于道路的什么位置？

例如 80m link：

bin0 → 0.000
bin1 → 0.125
bin2 → 0.250
...
bin7 → 0.875

这使不同 trajectory 中相同道路位置具有一致空间语义。

不建议 V1 直接使用车辆相对 traversal time 作为 Position Embedding。

因为：

Spatial Position
= geometry / location

Relative Traversal Time
= motion information

后者会随着不同车辆速度变化，不属于固定的位置编码。

如果后续需要，可以增加：

+ Relative Time Feature

作为独立 ablation，而不是代替空间 Position Embedding。

13. 单条 Trajectory Encoder

对于一个 modeling unit：

trajectory
    │
    ├── bin0 → [Δt, ratio, observed] + position
    ├── bin1 → [Δt, ratio, observed] + position
    ├── ...
    └── binN

经过：

Feature Projection
        ↓
Bin Tokens
        ↓
Transformer Encoder
        ↓
Trajectory Representation

得到：

[
r_k \in \mathbb{R}^{d}
]

对于一个 snapshot 中的 K 条 trajectory：

[
R =
[r_1,r_2,\ldots,r_K]
]

shape：

[K, d]

16. V1 需要固定的几个核心定义

Sample

一个训练 sample：

[
(	ext{modeling unit},\ anchor_time)
]

内部包含过去一个 window 中的多条 causally available trajectories。

Token 层级

需要区分两层 token：

Bin Token
= 一条 trajectory 内部的 10m 空间单元

Trajectory Token
= Trajectory Encoder 对整条 pass 得到的 representation

Multi-Trajectory MAE mask 的是：

Trajectory Token

而不是：

Bin Token

最终 Representation

最终下游任务主要使用：

CLS Token

表示：

某个 modeling unit 在 anchor time 下，由过去多条 trajectory 推断出的动态交通状态。
