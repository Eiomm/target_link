## 0. Codex 的能力边界（先读这节）

## 1. 业务目标（为什么做这次改造）

- 路线：raw（7 天滴滴北京走廊数据）→ `tools/build_curves_spark.py`（一个纯 SQL Spark 作业）→ curves 分片 + meta → `pretrain_stream` 流式 **CLS 预训练**（CurveMAE，下游接 ETA）。
- **问题**：7 天全量 = 11.4 亿次"车经过 link"（sample 级），单卡跑不动一个 epoch，且热路段严重冗余。
- **本次改造目标**：先按 **"每条完整 link 在 7 天内最多保留 N 条不同轨迹（整车保留）"** 下采样 raw，再走 build → 预训练。语料规模 ≈ 与北京路网规模成正比（≈ 1.8M link × N），自动去热段冗余、单卡可行。**N 可扫**（暂定 10）。

## 4. 改造任务清单（按序执行，每步含"做/交付/验收"）

### Step 1 — 给 `tools/build_curves_spark.py` 加 `--max-trajs-per-link N`（核心改动）

**规约（必须遵守）**
- `N>0` 启用；`N<=0` 或不传 = 完全不影响现有行为。
- 分组键 = **完整 link（`target_link_id`）**；单位 = **`sample_id`（整条轨迹，保留它的全部 bin / sub / 后续派生）**。
- 选择方式 = **确定性伪随机**：对每个 `(target_link_id, sample_id)` 生成稳定键（如 `F.hash(sample_id)` 或带 seed 盐的 hash），per-link 排序取前 N。**同一输入两次运行必须输出相同**（用固定 seed；不建议对 distinct 集逐行 `F.rand(seed)` 后跨两遍复用，易漂移——稳妥做法是直接以 sample_id 的 hash 排序）。
- 施加位置：`read + seg_mark==1` 过滤 **之后**、`n_rows_raw = raw.count()` **之前**（与现有 `--sample-fraction` 同一个位置）。`sample-fraction` 是**行级**随机，会把一条 sample 拆散——**限量必须 sample 级**；两者同时给就 `print` 警告并建议只用限量。
- **口径红线**：此开关在"输入 glob 覆盖 7 天 union"时才等价于"每周每 link ≤N"。若按天跑（DAY=单天），结果是"每天每 link ≤N"（≈ 每周 ≤7N）。交付说明里写清，默认用法是单次 7 天作业。
- 建议新增 `--cap-seed`（默认 42）便于复现；实现建议一个独立函数 `cap_trajs_per_link(df, n, seed)` 并单测其"整车保留 + per-link ≤n + 确定性"。

**交付**
- 代码 diff：arg 解析 + 函数 + 接入 main 流程。
- 本地小样例验证命令（Step 4 会给）。

### Step 2 — 让 `--inputs` 支持"7 天一次性"与提交脚本透传

- 现状：`build_curves_spark.py` 的 `--inputs` 是单个 glob；`scripts/submit_curves_yarn.sh` 用 `event_hour=${DAY}${HOURS}/part-*.parquet`。
- 要做：
  1. `--inputs` 支持**逗号分隔的多个 glob**（`args.inputs.split(',')` → `spark.read.parquet(*globs)`），用于精确限定 7 天 `17~23`（HDFS 上**存在 20260824 部分小时**，默认 glob 别误收；若想收 17~23：传两个 glob `event_hour=2026081[7-9]*` + `event_hour=2026082[0-3]*`，注意 shell 里要防 glob 展开/用引号，或直接逗号拼接写全）。
  2. `submit_curves_yarn.sh` 加 `MAX_TRAJS_PER_LINK`（默认 0）环境变量透传给 `--max-trajs-per-link`，加 `HOURS` 空=全年的用法示例注释；加 `INPUT_GLOB` 多值透传说明。
- **不要**现在去动 `--sample-fraction` 语义（保持向后兼容）。

### Step 3 — edges（分位桶）必须在"最终限量语料"上一次算

- `curves_meta.json.d` 里 y/v/len 的 percentile edges 是**全语料**统计。限量后只有一个作业、一套语料 → 天然自洽。**不要**把多天各自作业的 curves/meta 简单拼起来用（桶不一致）。
- 因此跑法 = **单次作业吃 7 天 raw**，而不是 7 个 day 作业再合并。

### Step 4 — 验证（先本地小样例，后 yarn 全量）

本地小样例（用户在服务器执行）：
```
# ① 不变式回归：N 不生效时与原 smoke3 语义一致（可用 data/raw_hdfs/event_hour=2026082007 1 小时）
# ② 限量自检：对同一小时加 N=3，检查输出里 每个 target_link_id 的 distinct sample_id ≤3，
#    且 同一 sample_id 的 bin 行数不减少（整车保留）、两次运行结果逐位一致（确定性）
# ③ 分区自检：curves 输出分片数 == --curves-partitions，且同 sample 只落一个分片
```
yarn 全量（用户执行，命令见 §5）：单次 7 天限量作业 → 检查产物 + 保留分布 vs §2 普查表（可加一个对比：限量后逐 link distinct traj ≤ N）。

### Step 5 — stream 正式预训练

- 换 `configs/pretrain_stream.yaml` 的 `data.shards` 指向限量产物目录，跑正式 stage①。
- 监控项：`L_rec`、attr 四头 acc（y/v/len 应明显 >1/16，hour >1/24）、**CLS 活性**（eval 时 CLS 置零，ΔL_rec 必须显著 >0，不涨=CLS 死亡=预训练无效）。

## 5. 数据怎么读（schema / 路径 / 跑法）

### 5.1 你能在本地直接读的样例
`target_link/data/raw_hdfs/event_hour=2026081708|2026082007|2026082008|2026082017|2026082107|2026082117` —— 每目录内 `part-*.parquet`（15 个/时）。**注意这些本地副本没有 `event_hour` 列**（那列只在 HDFS 分区目录上）；要日期就**从 `t_enter`（unix 秒）推**，例：

## 6. 已知坑（踩过，别重踩）

1. **minipy3 无 pandas/numpy**：executor 端只能纯 SQL / pyspark functions，不能 mapInPandas / 自定义 python UDF 数组运算。
2. **`--sample-fraction` 是行级**：会拆散一条 sample（丢一半 bin），不能用于 per-link 限量。
3. **`event_hour` 列本地副本没有**（见 §5.1）。
4. **精度**：SQL 端 T_diff/速度保留 double，npz 参照存 f32；逐位比对要先对齐精度，否则有 ~6e-5 假差异。`pandas` 里 `df.sub` 是减法方法名，取列必须 `df['sub']`。
5. **curves 分区必须是 sample_id hash**（防 train/val 样本级泄漏），回退 round-robin 会泄漏。
6. **edges 必须单语料一次算**（§Step 3）。
7. **dedup `.persist(DISK_ONLY)`** 在 local master 也会物化到盘，注意本地配额/目录。
8. `DataLoader` 的 `workers` 配置项读了没用（`num_workers` 硬编码 0）——已知，不用改。
9. HDFS 上 `beijing_week_biz/samples` 含 `20260824` 部分小时，glob 别默认收成"8 天"。

## 7. 待用户确认（Open Questions —— 决定代码怎么写前最好先定）

1. **"一条 link ≤N 条轨迹"的"轨迹"按哪个 ID？**
   - 数据里 `traj_id` 语义存疑：单日 distinct ~40 万，但官方"行程数"每天 ~500 万 → `traj_id` 疑似**持久车辆/司机 ID**（不是"单次行程"）。§2 普查的 per-link 分布就是按 distinct traj 算的。
   - 可选项：(a) 按 distinct traj_id（车，每天同车多次经过只算一条）；(b) 按 distinct sample/pass（经过次数，真正"多少车次经过"）；(c) 两个都支持，参数区分。
   - **默认先实现 (b) sample 级**（最贴近"经过次数"且与 samples/曲线单元 1:1），把 (a) 留作参数。
2. **N 初始值**：文档按 10 推演；5 / 10 / 20 的效果已给（§2），用户定。
3. **是否按 (link, hour) 分层**：7 天每 link 随机留 ≤N 可能让车集中在某几个钟点，伤 `attr_hour`/时段上下文。若要在意，改成按小时分摊（每 (link, hour-of-day) ≤ceil(N/…)）。用户定要不要。
4. **输入口径**：精确 7 天 = 20260817–23（排除 8/24）。
5. **day17 旧 round-robin 产物**是否仍重跑一次修复版当等价对照（成本低），用户定。
